# 088. Merge Sorted Array

- **链接**：https://leetcode.cn/problems/merge-sorted-array/
- **难度**：Easy
- **完成日期**：2026-09-21

## 思路：从后往前填

`nums1` 的长度是 `m + n`，但只有前 `m` 个是有效数据，**后半段是空的**，用来容纳 `nums2`。

关键就是利用这个空位：**从最大的元素开始，从后往前填。**

- `i` 指向 `nums1` 有效部分的末尾（下标 `m - 1`）
- `j` 指向 `nums2` 的末尾（下标 `n - 1`）
- `k` 指向 `nums1` 的最后一个位置（下标 `m + n - 1`）

每次比较 `nums1[i]` 和 `nums2[j]`，把**较大**的那个放到 `nums1[k]`，然后相应指针往前移。

## 为什么必须从后往前

假设从前往后填：

```
nums1 = [4, 5, 6, 0, 0, 0], nums2 = [1, 2, 3]
```

第一个位置 `nums1[0]` 是 `4`，会被 `nums2` 的 `1` 覆盖掉 —— **但 `4` 还没参与比较，它就这么丢了**。

从后往前填就不会有这个问题：我们写入的位置永远是**还没被读到**的空位。
`nums1` 末尾那三个 `0` 本来就是占位符，覆盖它们没有任何损失。

## 为什么循环结束后只处理 nums2

```java
while (j >= 0) {
    nums1[k--] = nums2[j--];
}
```

- **`nums2` 有剩余**：说明这些元素比 `nums1` 里剩下的都小，必须搬到 `nums1` 前面
- **`nums1` 有剩余**：不用管 —— 它们本来就在正确的位置上（这是从后往前填的额外好处）

这个不对称正是这题的巧妙之处，也是面试官爱问的点。

## 复杂度

- 时间：**O(m + n)**，每个元素最多被访问一次
- 空间：**O(1)**，直接在 `nums1` 上原地修改，没有用额外数组

这是这题的最优解。

## 关键点

- `i` 从 `m - 1` 开始，`j` 从 `n - 1` 开始，**不是**从 `length - 1` 开始（`nums1` 后半段是无效数据）
- `k--` 这种写法是"先用 `k` 的当前值，再减一"，一次完成写入和移动
- 题目要求返回 `void`，是**原地修改** `nums1`，不是返回新数组

## 易错点 / 踩过的坑

- 最容易犯的错是**从前往后填**，然后被覆盖问题绕进去（有人会额外开一个数组来存，那样空间就不是 O(1) 了）
- 忘记处理 `nums2` 的剩余元素，导致前面几个位置没被填上
- 多余的担心：去处理 `nums1` 的剩余元素（不需要，但处理了也不会错）
