# 001. Two Sum

- **链接**：https://leetcode.cn/problems/two-sum/
- **难度**：Easy
- **完成日期**：2026-09-21

## 两个解法对照

| 解法 | 文件 | 时间 | 空间 | 备注 |
|---|---|---|---|---|
| 暴力双层循环 | `SolutionBruteForce.java` | O(n²) | O(1) | 我自己先想出来的 |
| 哈希表一次遍历 | `SolutionHashMap.java` | O(n) | O(n) | 面试标准答案 |

## 解法一：暴力双层循环（我的第一版）

枚举所有数对 `(i, j)` 且 `j > i`，检查 `nums[i] + nums[j] == target`。

外层固定 `i`，内层从 `i + 1` 开始，这样避免了自己和自己相加、也避免重复检查同一对。

**提前退出**：找到第一组就返回。最初我写的是打印下标然后 `break outer` 跳出两层循环 ——
这个标签写法是对的，但改成 `return` 更直接：方法一返回，循环自然结束。

复杂度 O(n²)：n = 5 时比较 10 次，n = 10000 时约五千万次。数据一大会明显变慢。

## 解法二：哈希表一次遍历（标准答案）

一次遍历，用哈希表记录「已经见过的值 → 它的下标」。
走到 `nums[i]` 时，需要的另一半是 `target - nums[i]`，直接查表看它出现过没有。

**关键顺序：先查再存。** 如果先把当前元素存进去，当 `target` 恰好等于 `2 * nums[i]` 时，
会拿同一个元素用两次，得到错误答案。这个坑我在写的时候踩过。

为什么它比暴力快：暴力对每个 i 都要重新扫一遍剩下的元素（重复劳动），
哈希表把「找另一半」这一步从 O(n) 降到 O(1)，所以整体从 O(n²) 降到 O(n)。

## 为什么这题不能用双指针

双指针（左右夹逼）要求数组**有序**。这题要返回**原始下标**，一旦排序，下标就乱了，
得额外记录原位置才行。所以双指针不是这题的合适解法，看到有人这么写要留个心。

## 关键点

- 哈希表 key 存**值**，value 存**下标** —— 能一次遍历出结果就靠这个
- 不需要排序，不破坏原数组
- 找到立刻返回，不要继续遍历
- `int[]` 返回写法是 `new int[] { a, b }`

## 易错点 / 踩过的坑

- 哈希表版：一开始写成了先 `put` 再查，`[3, 3], target = 6` 这组用例过不了
- 用了 `HashSet` 然后想回头找下标，发现拿不到，只能用 `HashMap`
- 暴力版：一开始把逻辑全写在 `main` 里并直接 `System.out.println`，
  但 LeetCode 只认 `public int[] twoSum(int[] nums, int target)` 这个方法签名，
  写在 `main` 里是**粘贴不上去**的。必须把逻辑抽成方法、用 `return` 返回结果
